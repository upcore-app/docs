| Methode | Pfad | Scope |
| --- | --- | --- |
| `GET` | `/api/v1/incidents` | `incidents:read` |
| `POST` | `/api/v1/incidents` | `incidents:write` |
| `GET` | `/api/v1/incidents/{id}` | `incidents:read` |
| `PATCH` | `/api/v1/incidents/{id}` | `incidents:write` |
| `DELETE` | `/api/v1/incidents/{id}` | `incidents:write` |
| `POST` | `/api/v1/incidents/{id}/updates` | `incidents:write` |
| `PATCH` | `/api/v1/incidents/{id}/updates/{updateId}` | `incidents:write` |

Filter auf der Listenroute: `status`, `statusPageId`.

Die Status sind `investigating`, `identified`, `monitoring` und `resolved`.

## Eine eröffnen

Eine Störung hat immer mindestens einen Verlaufseintrag, `message` ist beim
Anlegen also Pflicht.

```bash [Terminal]
curl -X POST https://status.example.com/api/v1/incidents \
  -H "Authorization: Bearer $UPCORE_KEY" -H 'Content-Type: application/json' \
  -d '{
        "title": "Erhöhte Fehlerraten in der API",
        "message": "Wir untersuchen vermehrte 5xx-Antworten.",
        "statusPageIds": [1],
        "monitors": [{ "monitorId": 3, "impact": "degraded" }]
      }'
```

## Den Status bewegen

::caution
Der Status wird durch **das Posten eines Verlaufseintrags** bewegt, nicht durch
`PATCH`. Ein `PATCH` ändert Titel, Statusseiten und betroffene Monitore.
::

```bash [Terminal]
curl -X POST https://status.example.com/api/v1/incidents/7/updates \
  -H "Authorization: Bearer $UPCORE_KEY" -H 'Content-Type: application/json' \
  -d '{ "status": "identified", "message": "Ein fehlerhaftes Deploy hat die Fehler verursacht." }'
```

```bash [Terminal]
curl -X POST https://status.example.com/api/v1/incidents/7/updates \
  -H "Authorization: Bearer $UPCORE_KEY" -H 'Content-Type: application/json' \
  -d '{ "status": "resolved", "message": "Zurückgerollt, die Fehlerraten sind normal." }'
```

`resolved` zu posten setzt `resolvedAt`. Danach einen anderen Status zu posten
löscht es wieder — so wird eine Störung wiedereröffnet.

## Ein Update korrigieren

```bash [Terminal]
curl -X PATCH https://status.example.com/api/v1/incidents/7/updates/12 \
  -H "Authorization: Bearer $UPCORE_KEY" -H 'Content-Type: application/json' \
  -d '{ "message": "Ein fehlerhaftes Deploy war die Ursache; Rollback läuft." }'
```
