| Methode | Pfad | Scope |
| --- | --- | --- |
| `GET` | `/api/v1/monitors` | `monitors:read` |
| `POST` | `/api/v1/monitors` | `monitors:write` |
| `GET` | `/api/v1/monitors/{id}` | `monitors:read` |
| `PATCH` | `/api/v1/monitors/{id}` | `monitors:write` |
| `DELETE` | `/api/v1/monitors/{id}` | `monitors:write` |

Filter auf der Listenroute: `type`, `active`.

## Die richtigen Felder für den Typ senden

Welche Felder ein Monitor braucht, hängt an seinem `type`:

| type | Pflicht | Hinweise |
| --- | --- | --- |
| `http` | `target` | `target` muss mit `http://` oder `https://` beginnen |
| `keyword` | `target`, `keyword` | wie `http`, plus der Body muss `keyword` enthalten |
| `ping` | `target` | Hostname oder IP |
| `tcp` | `target`, `port` | |
| `dns` | `target` | `dnsRecordType` ist standardmäßig `A` |
| `ssl` | `target` | `port` ist standardmäßig `443` |
| `push` | – | ein `pushToken` wird erzeugt; Push an `GET /api/push/{pushToken}` |
| `group` | `memberIds` | aggregiert andere Monitore; Gruppen lassen sich nicht verschachteln |

## Einen Monitor anlegen

```bash [Terminal]
curl -X POST https://status.example.com/api/v1/monitors \
  -H "Authorization: Bearer $UPCORE_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
        "name": "API Gateway",
        "type": "keyword",
        "target": "https://api.example.com/health",
        "keyword": "\"status\":\"ok\"",
        "interval": 60,
        "failureThreshold": 3,
        "slaTarget": 99.9,
        "httpHeaders": [{ "name": "X-Probe", "value": "upcore" }]
      }'
```

## Einen ändern

Ein `PATCH` wird auf den aktuellen Monitor gemergt, und das Ergebnis wird **als
Ganzes** validiert — die Typregeln oben gelten also weiter.

```bash [Terminal]
curl -X PATCH https://status.example.com/api/v1/monitors/3 \
  -H "Authorization: Bearer $UPCORE_KEY" \
  -H 'Content-Type: application/json' \
  -d '{ "interval": 30 }'
```

::warning
Einen Monitor auf `tcp` umzustellen, ohne einen `port` mitzuschicken, wird
abgelehnt statt stillschweigend übernommen.
::

## Die Heartbeats lesen

`GET /api/v1/monitors/{id}` liefert zusätzlich die 50 jüngsten `heartbeats`.

| `status` | Zustand |
| --- | --- |
| `1` | up |
| `0` | down |
| `2` | pending — ein fehlgeschlagener Check, der `failureThreshold` noch nicht ausgeschöpft hat |
