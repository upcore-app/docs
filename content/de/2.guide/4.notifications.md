Ein Benachrichtigungskanal ist ein Ziel. Du konfigurierst ihn einmal unter
**Benachrichtigungen** und hängst ihn an die Monitore, die ihn nutzen sollen.

## Einen Kanal wählen

| Kanal | Was er braucht |
| --- | --- |
| **Discord** | Eine Webhook-URL. Optional ein Anzeigename. Postet ein farbiges Embed. |
| **Slack** | Eine Incoming-Webhook-URL. |
| **Microsoft Teams** | Eine Incoming-Webhook-URL. |
| **Google Chat** | Eine Space-Webhook-URL. |
| **Telegram** | Ein Bot-Token und eine Chat-ID. |
| **ntfy** | Ein Topic, und einen Server, falls nicht `ntfy.sh`. Optional ein Access-Token für ein geschütztes Topic und eine Priorität. |
| **Gotify** | Eine Server-URL und ein Application-Token. |
| **Pushover** | Ein User-Key und ein Application-Token. |
| **Webhook** | Eine URL. Das Ereignis wird als JSON gepostet, für was auch immer du damit vorhast. |

Jeder Kanal deklariert seine eigenen Felder, und als geheim markierte Felder —
Webhook-URLs, Tokens — werden nach dem Speichern nie im Klartext an den Browser
zurückgegeben.

## Einen Test senden

Jeder Kanal hat einen Test-Knopf. Er liefert dieselbe Form, die ein echtes
Ereignis hat, mit der Art `test` — ein falsch konfigurierter Webhook scheitert
also dort, wo du gerade hinschaust, statt um 3 Uhr nachts.

![Die Konfiguration eines Discord-Kanals — die gespeicherte Webhook-URL geht nie im Klartext zurück an den Browser](/screenshots/de/notification-config.jpg)

## Verstehen, was gesendet wird

Ein Ereignis trägt die Art (`up`, `down` oder `test`), einen einzeiligen Titel,
eine lesbare Meldung und den Monitor, um den es geht — Name, Typ und Ziel — plus
Latenz und, wo vorhanden, das fehlgeschlagene Detail.

Für einen **pending**-Heartbeat wird nichts gesendet. Ein Fehler unterhalb der
`failureThreshold` des Monitors wird festgehalten und bleibt dort; nur der Übergang
auf down und zurück auf up wird gemeldet.

## Discord richtig nutzen

Discord ist zweimal konfigurierbar, für zwei verschiedene Aufgaben:

- Als **Benachrichtigungskanal** per Webhook, wie die anderen.
- Als **Bot**, unter einem eigenen Admin-Bereich — das ist, was upcore erlaubt,
  eine Störungsnachricht mitzuziehen, indem es sie bearbeitet statt neu zu posten.

Das Bot-Token liegt auf dem Server und verlässt ihn nie unmaskiert.

## Einen Kanal im Code ergänzen

Die Registry ist eine Datei. Ein Provider ist ein eigenständiges Modul, das
deklariert, welche Konfigurationsfelder es braucht, und das ein Ereignis zustellen
kann; Validierung, Maskierung von Geheimnissen, das Admin-Formular und der Versand
sind generisch und werden von diesen Deskriptoren getrieben.

Einen Kanal hinzuzufügen heißt: eine Datei unter
`server/notifications/providers/` und eine Zeile in `providers/index.ts`, die auch
die Reihenfolge der Kanäle festlegt.
