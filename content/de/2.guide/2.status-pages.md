Eine Statusseite ist eine öffentliche URL — `/status/<slug>` — die eine
ausgewählte Menge Monitore zeigt. Du kannst beliebig viele haben: eine für Kunden,
eine für die interne Plattform, eine je Produkt. Ein Monitor darf auf mehreren
stehen.

## Eine Seite anlegen

Unter **Status-Pages** im Admin-UI. Eine Seite braucht einen Slug und eine Menge
Monitore; alles andere hat einen Standard.

Monitore lassen sich auf der Seite gruppieren, sodass Leser *API*, *Web* und
*Worker* sehen statt einer flachen Liste aus neunzehn Namen.

::note
Slugs von Statusseiten sind instanzweit eindeutig. Eine
öffentliche Seite wird von außen verlinkt, also muss `/status/<slug>` genau eine
Seite benennen — unter welchem Host sie auch geöffnet wird.
::

## Sie gestalten

Das Design liegt im Admin-UI, nicht in einem Stylesheet, das du ausrollen musst:

- **Logo** — hochgeladen, neben der Datenbank gespeichert.
- **Primärfarbe**, Hintergrund-, Karten- und Textfarben.
- **Schrift** — neun selbst gehostete Schnitte (Inter, Lexend Deca, Montserrat,
  Open Sans, Roboto, Nunito, Lato, Ubuntu, Poppins). Nichts kommt von einem
  Google-CDN.
- **Eckenradius**.
- **Eigenes CSS**, für alles, was die Felder darüber nicht erreichen.

Eine hell gebrandete Seite wird hell — das Admin-UI ist nur dunkel, die
öffentlichen Seiten sind es nicht.

## Festlegen, was sie sagt

| | |
| --- | --- |
| Footer-Text | Freier Text unter den Monitoren. |
| Impressum und Datenschutz | Wo eine Rechtsordnung sie verlangt. |
| „Powered by upcore“ | Lässt sich entfernen. |
| SEO- und OpenGraph-Tags | Pro Seite — Titel, Beschreibung, Bild. |
| Heartbeat-Zeitfenster | Wie weit die Balken auf der öffentlichen Seite zurückreichen. |
| Standorte | Ob die Seite nennt, von welchen Outposts ein Monitor geprüft wird. |

::note
Die Standorte zu nennen ist standardmäßig aus. Welche Probes existieren, ist
Infrastruktur, und das zu veröffentlichen sollte eine Entscheidung sein statt ein
Nebeneffekt davon, Outposts zu benutzen. Die öffentliche Ansicht ist bewusst enger
als die im Admin: Name, Stadt, Land und die letzte Laufzeit — keine
Check-Meldungen, die ein internes Ziel nennen könnten.
::

## Die Sprache der Besucher sprechen

Die öffentlichen Seiten sind zweisprachig, Deutsch und Englisch, pro Besucher
gewählt. Die Sprache hängt an einem Cookie statt an einem URL-Segment, damit
`/status/<slug>` die Adresse bleibt, die du herausgegeben hast — in einem bereits
gesetzten Lesezeichen taucht kein `/de/` auf.

## Einen einzelnen Monitor anderswo zeigen

Zwei Wege, für zwei verschiedene Orte:

- **`/embed/<slug>/<monitor>`** — ein iframe-Widget für eine Seite, die dir
  gehört.
- **`/badge/<slug>/<monitor>/<kind>.svg`** — ein Bild, für eine README, wo jeder
  Markdown-Renderer ein iframe entfernt.

Beide sind so öffentlich wie die Statusseite, zu der sie gehören, und beide melden
denselben Zustand wie die Seite. Siehe
[Embeds & Badges](/de/guide/embeds-and-badges).
