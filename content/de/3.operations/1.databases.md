`DB_DRIVER` wählt `sqlite` (der Standard) oder `postgres`. Keines von beiden ist
das echte mit dem anderen drangeschraubt.

## Mit SQLite anfangen

Eine Datei, kein Server, kein Setup. Sie liegt unter
`<UPCORE_DATA_DIR>/upcore.db` — im Container `/data/upcore.db`, aus einem Volume,
und überlebt damit ein Deploy. Hochgeladene Icons für Statusseiten liegen daneben
in `<UPCORE_DATA_DIR>/icons`.

Das ist die richtige Wahl für einen einzelnen Container, also für die meisten
Deployments.

```ini [.env]
DB_DRIVER=sqlite
UPCORE_DATA_DIR=/data
```

Sichere sie, indem du die Datei bei gestoppter App kopierst, oder im laufenden
Betrieb mit `sqlite3 upcore.db ".backup"`.

## Auf PostgreSQL wechseln

Für ein geteiltes oder repliziertes Deployment.

```ini [.env]
DB_DRIVER=postgres
DATABASE_URL=postgres://upcore:secret@db:5432/upcore
```

Im Docker-Stack ergänzt du die Override-Datei und setzt `POSTGRES_PASSWORD`; die
URL wird für dich gebaut:

```bash [Terminal]
docker compose -f docker-compose.yml -f docker-compose.postgres.yml up -d
```

::warning
Ein Wechsel von `DB_DRIVER` verschiebt **keine** Daten. Die neue Datenbank startet
leer. Es gibt keine eingebaute Migration zwischen beiden — exportiere und
importiere selbst, wenn du Zeilen hast, die dir etwas wert sind.
::

Ein Passwort mit Sonderzeichen muss URL-kodiert werden — der Wert ist Teil einer
URL. `openssl rand -hex 24` liefert eines, das keine Kodierung braucht.

## Wissen, was „beides unterstützt“ kostet

Wenn du Code beiträgst, ist das der Teil, der dich bindet. Jede Regel unten
existiert, weil eine für einen Treiber geschriebene Query sich auf dem anderen
still falsch verhält.

::u-page-grid
  :::u-page-card
  ---
  icon: i-lucide-timer
  variant: subtle
  ---
  #title
  Jede Query wird awaited

  #description
  `better-sqlite3` ist synchron, und Drizzle bildet das als `.all()` / `.get()` /
  `.run()` ab. Für Postgres gibt es das nicht — und ein Drizzle-Query-Builder, der
  nie awaited wird, läuft nie, was kein Typfehler fängt. Diese drei Methoden
  kommen in `server/` nirgends vor.
  :::

  :::u-page-card
  ---
  icon: i-lucide-copy
  variant: subtle
  ---
  #title
  Jede Tabelle existiert zweimal

  #description
  `schema.sqlite.ts` und `schema.pg.ts`. `schema.ts` wählt das zu `DB_DRIVER`
  passende Paar und ist das einzige, das alles andere importieren darf. Eine
  Spalte, die zu einem Zwilling kommt, muss auch zum anderen; Enums leben einmal,
  in `constants.ts`.
  :::

  :::u-page-card
  ---
  icon: i-lucide-file-code
  variant: subtle
  ---
  #title
  Das SQL muss portabel sein

  #description
  Kein `datetime('now')`, `date('now')`, `strftime` und kein zweiargumentiges
  `MAX` — das sind SQLite-Eigenheiten. Zeitgrenzen werden in JavaScript berechnet
  und als Werte übergeben.
  :::

  :::u-page-card
  ---
  icon: i-lucide-sigma
  variant: subtle
  ---
  #title
  Aggregate brauchen einen Cast

  #description
  Postgres typisiert `COUNT`/`SUM` als bigint und `AVG` als numeric, und
  node-postgres liefert beides als **String** zurück. Also
  `CAST(COUNT(*) AS INTEGER)` und `CAST(AVG(…) AS DOUBLE PRECISION)`.
  :::
::

Beide Zwillinge speichern Zeitstempel bewusst als `TEXT` und Booleans als
`INTEGER` 0/1, sodass eine gelesene Zeile für den Code darüber ununterscheidbar
ist.

## Einen Zeitstempel lesen

Zeitstempel werden als `'YYYY-MM-DD HH:MM:SS'` in UTC gespeichert und sortieren
als Strings. Das Format trägt keine Zone, sie zu parsen heißt also, „UTC“
ausdrücklich zu sagen — und die API gibt genau dieselben Strings heraus, die die
App parst.

## Prüfen, ob sie antwortet

```bash [Terminal]
curl -s https://status.example.com/api/health
```

`GET /api/health` meldet, ob die Datenbank antwortet **und** ob die Migrationen
gelaufen sind. Das ruft der Container-Healthcheck auf, und es ist öffentlich.
