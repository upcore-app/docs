Lass `NUXT_SMTP_HOST` leer — der Standard — und upcore verschickt **gar nichts**:
keine Adressbestätigung, keinen Passwort-Reset, keine Willkommensmail. Eine
selbst gehostete Instanz bleibt genau so, wie sie war, bis jemand sie auf ein Relay
richtet.

Genau das macht die Adressbestätigung dort, wo ein Relay existiert, sicher
*verpflichtend*: eine Instanz, die die Bestätigungsmail nicht senden kann, legt
nie ein Konto an, das auf eine wartet — niemand wird von einem Server ausgesperrt,
den du nie eingerichtet hast.

## Auf ein Relay richten

```ini [.env]
NUXT_SMTP_HOST=smtp.eu.mailgun.org
NUXT_SMTP_PORT=587
NUXT_SMTP_USER=postmaster@mg.example.com
NUXT_SMTP_PASSWORD=…
NUXT_SMTP_FROM=status@example.com
NUXT_SMTP_FROM_NAME=upcore
```

| | |
| --- | --- |
| `587` | STARTTLS. Der Standard. |
| `465` | Implizites TLS, allein am Port erkannt. |
| `NUXT_SMTP_SECURE=true` | Erzwingt implizites TLS auf einem anderen Port. Fast nie nötig. |

`NUXT_SMTP_FROM` fällt auf `NUXT_SMTP_USER` zurück, wenn das eine Adresse ist —
was die meisten Relays ohnehin verlangen.

## Es verschlüsselt halten

```ini [.env]
NUXT_SMTP_REQUIRE_TLS=true
NUXT_SMTP_REJECT_UNAUTHORIZED=true
```

Beides standardmäßig an.

::caution
Schalte `NUXT_SMTP_REQUIRE_TLS` nur für ein Relay auf localhost aus, das kein
STARTTLS anbietet. Ausgeschaltet gehen die Zugangsdaten oben im Klartext über die
Leitung.
::

Schalte `NUXT_SMTP_REJECT_UNAUTHORIZED` nur für ein privates Relay aus, dessen
selbstsigniertes Zertifikat du kennst.

## Entscheiden, ob Adressen bestätigt werden

```ini [.env]
NUXT_EMAIL_VERIFICATION=true
```

Standardmäßig an, und nur dort wirksam, wo ein Relay konfiguriert ist.

Damit wird ein selbst registriertes Konto beim Login abgewiesen, bis der Link in
der Bestätigungsmail geöffnet wurde, und ein Konto, das nie bestätigt, wird nach
30 Tagen gelöscht — in der upcore Cloud zusammen mit der Organisation, die es
angelegt hat und der sonst nie jemand beigetreten ist.

::note
Diese Löschung ist überhaupt der Grund für das Flag: eine Instanz, die
Registrierungen an Leute vergibt, die sie ohnehin kennt, will die Hürde
vielleicht nicht. Auf `false` sind Registrierungen sofort offen, nichts wird
wegen fehlender Bestätigung gelöscht, und die Willkommensmail rückt an die
Registrierung.
::

Alles andere bleibt unberührt. Ein Konto, das ein Admin, der Operator oder ein
Identity-Provider angelegt hat, ist durch seine Entstehung bestätigt — jemand, dem
schon vertraut wurde, hat entschieden, dass es existiert — und der Passwort-Reset
funktioniert so oder so.

## Wissen, was verschickt wird

| Mail | Wann |
| --- | --- |
| Adressbestätigung | Bei einer Selbstregistrierung, wo die Bestätigung an ist. |
| Willkommen | Nach der Bestätigung — oder bei der Registrierung, wo die Bestätigung aus ist. |
| Passwort-Reset | `/api/auth/password-reset`, das ohne Relay mit `404` antwortet. |

Mail wird in der Sprache verfasst, die die Person gerade gelesen hat, als sie
ausgelöst wurde.
