Die HTTP-Seite braucht nichts: ein Request trägt seinen eigenen Zustand und die
Session ist ein versiegeltes Cookie — ein auf fünf skalierter Swarm-Service
braucht also keine Sticky Sessions.

Das Problem sind die **Timer**. Ein Nitro-Plugin läuft in jedem Prozess, und ihr
Zustand ist *was habe ich schon getan*. Ohne Weiteres prüfen fünf Replicas jeden
Monitor fünfmal, fragen jeden Outpost fünfmal, senden jede Benachrichtigung
fünfmal und führen den stündlichen Lauf, der unbestätigte Konten löscht, fünfmal
aus.

## Die Schedules einen Leader wählen lassen

```ini [.env]
NUXT_SCHEDULER=auto
```

Der Standard, und für jedes Deployment richtig. Jeder Hintergrund-Job hält ein
**Lease** — eine Zeile in einer Tabelle `runner_leases` — und eines zu
beanspruchen ist ein einziges Statement, dessen `WHERE`-Klausel die ganze
Entscheidung ist: *meins zum Erneuern, oder niemandes zum Nehmen*. Die Datenbank
serialisiert das, also gewinnt genau ein Prozess.

Erneuern ist dasselbe Statement wie Beanspruchen — das Ticken *ist* also das
Lebenszeichen. Ein sterbender Container wird in Sekunden ersetzt. Für einen
Container gibt es nichts zu konfigurieren, und für zwanzig auch nicht.

::note
Ein Prozess, der das Lease verliert, wirft weg, was er sich über den Schedule
gemerkt hat. Behielte er es, würde ein neu erworbenes Lease Monitore überspringen;
weggeworfen liest die nächste Runde die Wahrheit aus den Heartbeats zurück.
::

## Wissen, was das Lease nicht ist

::u-page-grid
  :::u-page-card
  ---
  icon: i-lucide-unlock
  variant: subtle
  ---
  #title
  Kein Lock

  #description
  Nichts zäunt eine bereits laufende Runde ein. Eine Übergabe, die sich um eine
  Runde überlappt, schreibt einen doppelten Heartbeat — kosmetisch. Verhindert
  wird, dass *jede* Runde auf jedem Replica für immer verdoppelt wird.
  :::

  :::u-page-card
  ---
  icon: i-lucide-building
  variant: subtle
  ---
  #title
  Nicht organisationsbezogen

  #description
  Die Leases sind eine Eigenschaft des Deployments, nicht einer Organisation.
  :::

  :::u-page-card
  ---
  icon: i-lucide-clock
  variant: subtle
  ---
  #title
  Nicht an der Datenbankuhr gemessen

  #description
  `datetime('now')` und `now()` sind nicht dasselbe SQL, und Portabilität ist mehr
  wert als ein paar Sekunden Genauigkeit. Uhrendrift kostet höchstens eine TTL
  Verzögerung, nachdem ein Halter stirbt.
  :::
::

## Die Rollen stattdessen aufteilen

Für ein Deployment, das die Aufgabe lieber zuweist, als sie zu wählen:

```ini [.env]
# auf den Web-Replicas
NUXT_SCHEDULER=off
```

```ini [.env]
# auf einem dedizierten Runner-Service
NUXT_SCHEDULER=on
```

::warning
`on` prüft nichts. Zwei Prozesse damit verdoppeln jeden Check, jede
Benachrichtigung und jeden Aufbewahrungslauf. Genau ein Service darf es tragen.
::

## Hinter einem Proxy sitzen

Mit mehr als einem Replica gibt es einen Load Balancer, und damit
`NUXT_TRUST_PROXY=true` — sonst scheint jeder Request vom Proxy zu kommen.

```ini [.env]
NUXT_TRUST_PROXY=true
```

Nur hinter einem Proxy, den du kontrollierst. Die CIDR-Bindung von API-Keys liest
`x-forwarded-for`, und ein nicht vertrauenswürdiger Proxy lässt Aufrufer ihre
Quelladresse selbst wählen.
