| Method | Path | Scope |
| --- | --- | --- |
| `GET` | `/api/v1/monitors` | `monitors:read` |
| `POST` | `/api/v1/monitors` | `monitors:write` |
| `GET` | `/api/v1/monitors/{id}` | `monitors:read` |
| `PATCH` | `/api/v1/monitors/{id}` | `monitors:write` |
| `DELETE` | `/api/v1/monitors/{id}` | `monitors:write` |

Filters on the list route: `type`, `active`.

## Send the right fields for the type

Which fields a monitor needs depends on its `type`:

| type | required | notes |
| --- | --- | --- |
| `http` | `target` | `target` must start with `http://` or `https://` |
| `keyword` | `target`, `keyword` | like `http`, plus the body must contain `keyword` |
| `ping` | `target` | hostname or IP |
| `tcp` | `target`, `port` | |
| `dns` | `target` | `dnsRecordType` defaults to `A` |
| `ssl` | `target` | `port` defaults to `443` |
| `push` | – | a `pushToken` is minted; push to `GET /api/push/{pushToken}` |
| `group` | `memberIds` | aggregates other monitors; groups cannot be nested |

## Create a monitor

```bash [Terminal]
curl -X POST https://status.example.com/api/v1/monitors \
  -H "Authorization: Bearer $UPCORE_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
        "name": "API Gateway",
        "type": "keyword",
        "target": "https://api.example.com/health",
        "keyword": "\"status\":\"ok\"",
        "interval": 60,
        "failureThreshold": 3,
        "slaTarget": 99.9,
        "httpHeaders": [{ "name": "X-Probe", "value": "upcore" }]
      }'
```

## Update one

A `PATCH` is merged onto the current monitor and the result is validated **as a
whole**, so the type rules above still hold.

```bash [Terminal]
curl -X PATCH https://status.example.com/api/v1/monitors/3 \
  -H "Authorization: Bearer $UPCORE_KEY" \
  -H 'Content-Type: application/json' \
  -d '{ "interval": 30 }'
```

::warning
Switching a monitor to `tcp` without also sending a `port` is rejected rather than
silently accepted.
::

## Read the heartbeats

`GET /api/v1/monitors/{id}` additionally returns the 50 most recent `heartbeats`.

| `status` | State |
| --- | --- |
| `1` | up |
| `0` | down |
| `2` | pending — a failed check that has not yet used up `failureThreshold` |
