- **Base path:** `/api/v1`
- **Spec:** `GET /api/v1/openapi.json`, generated from the same zod schemas the
  endpoints validate against
- **Interactive docs:** `/api-docs` on your instance

Because the spec is generated from the validation, it cannot describe an endpoint
that does not exist.

## Send a key

Every request needs an API key, passed either way:

::code-group
```bash [Authorization]
curl -H "Authorization: Bearer upc_ac262397_3307862…" \
     https://status.example.com/api/v1/monitors
```

```bash [X-API-Key]
curl -H "X-API-Key: upc_ac262397_3307862…" \
     https://status.example.com/api/v1/monitors
```
::

Keys are created in the admin UI under **API keys**, admin role required. The
token has the form `upc_<prefix>_<secret>` and is shown **exactly once** — only
`sha256(secret)` is stored, so a lost key is replaced, not recovered.

::note
A logged-in admin's session cookie is accepted as a fallback. That is what makes
the "Test request" button on `/api-docs` work; scripts should always use a key.
::

Key management is not exposed through `/api/v1`. A key can never create, modify
or read another key.

## Grant scopes

| Scope | Grants |
| --- | --- |
| `monitors:read` | list and read monitors |
| `monitors:write` | create, update, delete monitors |
| `incidents:read` | list and read incidents |
| `incidents:write` | create, update, delete incidents and post timeline updates |
| `maintenances:read` | list and read maintenance windows |
| `maintenances:write` | create, update, delete windows and post timeline updates |

`<resource>:write` implies `<resource>:read`. A request without the required
scope returns `403`.

## Bind a key to a network

A key can be restricted to a list of networks. A request from any other address
is rejected with `403`, even when the key itself is valid.

```
203.0.113.0/24
2001:db8::/32
198.51.100.7
```

Both IPv4 and IPv6 are supported; a bare address binds the key to that single
host. An empty list allows every source address.

Host bits are normalized away on save, so `10.1.2.3/8` is stored — and matched —
as `10.0.0.0/8`. An IPv4 address arriving over a dual-stack listener as
`::ffff:203.0.113.7` still matches an IPv4 network. A network of one family never
matches an address of the other: `0.0.0.0/0` does not open the door for IPv6.

::warning{title="Behind a reverse proxy"}
Set `NUXT_TRUST_PROXY=true` so the source address is read from
`x-forwarded-for`. Without it the check uses the TCP peer address, which behind a
proxy is the proxy itself — every bound key would be rejected.

Only enable it when the proxy is one you control. Otherwise a caller sets the
header themselves and the binding is worthless.
::

In dev the header is always trusted, because requests reach the server through
Vite's dev proxy and the socket address is not visible there. In a production
build only `NUXT_TRUST_PROXY` decides.

## Expire and revoke

A key may carry an `expiresAt`. Expired and deactivated keys return `401`.
Deleting a key takes effect immediately.

## Read an error

Every non-2xx response uses one envelope:

```json
{
  "statusCode": 400,
  "statusMessage": "Invalid request body: target — HTTP target must start with http:// or https://",
  "data": {
    "issues": [
      {
        "path": "target",
        "message": "HTTP target must start with http:// or https://",
        "code": "custom"
      }
    ]
  }
}
```

`data.issues` is present on validation failures and names every offending field.

| Status | Meaning |
| --- | --- |
| `400` | invalid body, query or path parameter; or a referenced id does not exist |
| `401` | no key, unknown key, disabled key, expired key |
| `403` | key lacks the scope, or the request came from outside its CIDR binding |
| `404` | the addressed resource does not exist |

## Follow the conventions

- All bodies are JSON.
- `PATCH` is a partial update: only the fields you send change. An explicit
  `null` clears a nullable field.
- Timestamps are UTC. Datetimes are accepted as `YYYY-MM-DD HH:MM:SS` or ISO
  8601, and always returned as `YYYY-MM-DD HH:MM:SS`.
- List endpoints take `limit` (1–200, default 50) and `offset`.
- Ids referenced in a body — monitors, status pages, notifications — are checked
  before anything is written, so a bad reference never leaves a partial resource.

## Name the organization

On an organization's own subdomain, the key and the host must agree. On a host
where no organization resolves, the key supplies it — so a client does not have to know the
hostname layout.
