A notification channel is a destination. You configure it once under
**Notifications** and attach it to the monitors that should use it.

## Choose a channel

| Channel | What it needs |
| --- | --- |
| **Discord** | A webhook URL. Optional display name. Posts a colour-coded embed. |
| **Slack** | An incoming webhook URL. |
| **Microsoft Teams** | An incoming webhook URL. |
| **Google Chat** | A space webhook URL. |
| **Telegram** | A bot token and a chat id. |
| **ntfy** | A topic, and a server if not `ntfy.sh`. Optional access token for a protected topic, and a priority. |
| **Gotify** | A server URL and an application token. |
| **Pushover** | A user key and an application token. |
| **Webhook** | A URL. The event is posted as JSON, for whatever you want to do with it. |

Every channel declares its own fields, and fields marked secret — webhook URLs,
tokens — are never sent back to the browser in clear text once saved.

## Send a test

Each channel has a test button. It delivers the same shape a real event has, with
kind `test`, so a misconfigured webhook fails where you are looking at it rather
than at 3 a.m.

![A Discord channel's configuration — the saved webhook URL is never sent back to the browser in clear text](/screenshots/en/notification-config.jpg)

## Understand what is sent

An event carries the kind (`up`, `down` or `test`), a one-line title, a readable
message, and the monitor it is about — its name, type and target — plus the
latency and the failing detail where there is one.

Nothing is sent for a **pending** heartbeat. A failure below the monitor's
`failureThreshold` is recorded and stays there; only the transition to down, and
back to up, is announced.

## Use Discord properly

Discord is configured twice over, for two different jobs:

- As a **notification channel**, via webhook, like the others.
- As a **bot**, under its own admin section — which is what lets upcore keep an
  incident message in sync as the incident develops, editing rather than
  reposting.

The bot token is stored on the server and never leaves it unmasked.

## Add a channel to the code

The registry is one file. A provider is a self-contained module that declares
which config fields it needs and knows how to deliver an event; validation,
secret masking, the admin form and the dispatch are all generic and driven by
those descriptors.

Adding a channel means adding one file under `server/notifications/providers/`
and one line in `providers/index.ts`, which also defines the order the channels
appear in.
