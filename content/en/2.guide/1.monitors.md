A monitor is one thing you want to know the state of. It carries a check type, a
target, an interval, a timeout and a failure threshold, and it produces a stream
of heartbeats.

## Pick a check type

| Type | Requires | What it does |
| --- | --- | --- |
| `http` | `target` | Requests the URL and checks the status code. `target` must start with `http://` or `https://`. |
| `keyword` | `target`, `keyword` | Like `http`, and the response body must contain `keyword`. |
| `ping` | `target` | ICMP echo to a hostname or IP. |
| `tcp` | `target`, `port` | Opens a TCP connection. |
| `dns` | `target` | Resolves a name. `dnsRecordType` defaults to `A`. |
| `ssl` | `target` | Inspects the certificate. `port` defaults to `443`. |
| `push` | — | Inverted: the job calls upcore. A `pushToken` is minted on creation. |
| `group` | `memberIds` | Has no check of its own. Aggregates other monitors. |

### Add an HTTP or keyword check

Both take a custom HTTP method and request headers, which is what makes them
usable against an authenticated health endpoint:

```json
{
  "name": "API Gateway",
  "type": "keyword",
  "target": "https://api.example.com/health",
  "keyword": "\"status\":\"ok\"",
  "httpHeaders": [{ "name": "X-Probe", "value": "upcore" }]
}
```

### Add a push monitor

A `push` monitor is for work that calls *in* — cron runs, workers, backups.
upcore mints a token and the job pushes to it when it finishes:

```bash [crontab]
0 3 * * * /usr/local/bin/backup.sh && curl -fsS https://status.example.com/api/push/<pushToken>
```

If the push does not arrive within the interval, the monitor goes down. That is
the only check type where silence is the failure.

### Group monitors together

A `group` monitor aggregates the monitors in its member list and reports one
state for all of them. Groups cannot be nested, and they never run a check of
their own — there is nothing for a remote location to do, which is why a group is
always checked locally.

## Decide when a failure counts

Three settings per monitor, and together they decide how loud a blip is.

| Setting | |
| --- | --- |
| `interval` | Seconds between checks. |
| `timeout` | How long a single check may take before it counts as failed. |
| `failureThreshold` | How many failures in a row make the monitor *down*. |

Failures below the threshold are recorded as **pending** — status `2` — and never
wake anyone up. Nothing is sent, and the status pages do not turn red.

::note
A monitor with `failureThreshold: 3` on a 60-second interval takes three minutes
of continuous failure before it is announced. Raise the threshold on a target
that is known to flap; lower it on one where every second counts.
::

## Track an SLA

A monitor can carry an SLA target — 99.9 % over a 30-day window, say — and upcore
tracks the achieved figure against it. It appears on the monitor, and on any
status page configured to show it.

The window is rolling, and the figure is computed from the same heartbeats
everything else reads.

## Read the heartbeats

`GET /api/v1/monitors/{id}` returns the 50 most recent heartbeats alongside the
monitor. Their `status` is:

| Value | State |
| --- | --- |
| `1` | up |
| `0` | down |
| `2` | pending |

How much history is kept is a per-instance retention setting, not a per-monitor
one. On [upcore Cloud](/cloud/overview) your plan caps it.

## Check from more than one place

By default a monitor is checked by the upcore process itself. Two fields change
that:

| Field | Values | |
| --- | --- | --- |
| `check_strategy` | `local`, `outposts`, `both` | Who runs the check. |
| `outpost_policy` | `any`, `majority`, `all` | How the locations' verdicts are folded into one. |

`push` and `group` monitors are always `local`: neither describes work a remote
process could do. See [Outposts](/guide/outposts).

## Change a monitor safely

A `PATCH` is merged onto the current monitor and the **result** is validated as a
whole, so the type rules above still hold. Switching a monitor to `tcp` without
also sending a `port` is rejected rather than silently accepted.

See the [API reference](/api/monitors).
