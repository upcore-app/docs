title: Running more than one container
description: The HTTP side scales by itself. The background schedules are leased,
  so exactly one process runs them.

---

The HTTP side needs nothing: a request carries its own state and the session is a
sealed cookie, so a Swarm service scaled to five needs no sticky sessions.

The **timers** are the problem. A Nitro plugin runs in every process, and their
state is *what did I already do*. Left alone, five replicas check every monitor
five times, ask every outpost five times, send every notification five times, and
run the hourly pass that deletes unverified accounts five times.

## Let the schedules elect a leader

```ini [.env]
NUXT_SCHEDULER=auto
```

The default, and right for every deployment. Each background job holds a **lease**
— one row in a `runner_leases` table — and claiming one is a single statement
whose `WHERE` clause is the whole decision: *mine to renew, or nobody's to take*.
The database serializes it, so exactly one process wins.

Renewing is the same statement as claiming, which means ticking *is* the liveness
signal. A container that dies is replaced within seconds. There is nothing to
configure for one container, and nothing to configure for twenty.

::note
A process that loses the lease drops what it remembered about the schedule. Kept,
it would make a re-acquired lease skip monitors; dropped, the next round reads
the truth back out of the heartbeats.
::

## Know what the lease is not

::u-page-grid
  :::u-page-card
  ---
  icon: i-lucide-unlock
  variant: subtle
  ---
  #title
  Not a lock

  #description
  Nothing fences a round already in flight. A handover that overlaps by one round
  writes a duplicate heartbeat, which is cosmetic. What this prevents is *every*
  round being duplicated on every replica forever.
  :::

  :::u-page-card
  ---
  icon: i-lucide-building
  variant: subtle
  ---
  #title
  Not organization-scoped

  #description
  The leases are a property of the deployment, not of an organization.
  :::

  :::u-page-card
  ---
  icon: i-lucide-clock
  variant: subtle
  ---
  #title
  Not measured against the database clock

  #description
  `datetime('now')` and `now()` are not the same SQL, and portability is worth
  more than a few seconds of precision. Clock skew costs at most one TTL of delay
  after a holder dies.
  :::
::

## Split the roles instead

For a deployment that would rather assign the job than elect it:

```ini [.env]
# on the web replicas
NUXT_SCHEDULER=off
```

```ini [.env]
# on one dedicated runner service
NUXT_SCHEDULER=on
```

::warning
`on` checks nothing. Two processes carrying it duplicate every check, every
notification and every retention pass. Exactly one service may have it.
::

## Sit behind a proxy

With more than one replica there is a load balancer, which means
`NUXT_TRUST_PROXY=true` — otherwise every request appears to come from the proxy.

```ini [.env]
NUXT_TRUST_PROXY=true
```

Only behind a proxy you control. The API key CIDR binding reads
`x-forwarded-for`, and an untrusted proxy lets a caller pick their own source
address.
